# 🎬 MovieMood

**〜 観る前の「気分」も、観た後の「感想」も、映画と一緒に。〜**

MovieMood は、映画を観る前の期待や気分、鑑賞後の感想を記録・共有できる映画レビュー Web アプリケーションです。

映画の評価点だけでは伝えきれない感情をタグで表現し、ユーザー同士のコミュニケーションを通じて、新しい映画との出会いを楽しめることを目指しています。

## 1. 制作背景・目的

映画を観た後に感想を記録したり、観る前に期待している気持ちを残したりすることで、映画鑑賞をより楽しめるアプリケーションを作りたいと考え、MovieMood を制作しました。

一般的な映画レビューでは、評価点や文章による感想が中心となります。MovieMood では、それらに加えて、映画を観る前と観た後の気持ちを感情タグで表現できるようにしました。

また、いいねやコメントなどの交流機能を設けることで、ほかのユーザーの感想を参考にしながら、自分では知らなかった映画に興味を持つきっかけを提供します。

### 制作の目的

- 映画を観る前の期待や気分を記録する
- 鑑賞後の感想や評価を残す
- 感情タグによって、映画から受けた印象を直感的に表現する
- ユーザー同士の交流を通じて、新しい映画との出会いを増やす

## 2. 主な機能

### 🌙 TODAY'S PICKUP（日替わりムード・レコメンド）

日付のハッシュ値を利用した仕組みにより、「今日の Mood」と「おすすめ映画」を日替わりで提案します。同じ日付では同じ内容が表示される設計です。

### 🎥 映画情報の表示・リアルタイム検索

TMDB API を利用して映画情報を取得し、作品の詳細確認や検索ができます。

- ポスター画像、あらすじ、ジャンル、監督、上映時間、評価などの詳細表示
- 検索窓への入力に応じたオートコンプリート（検索候補プレビュー）
- 天気情報（OpenWeatherMap API）に合わせたおすすめ映画の提案
- TMDB の作品ページへのリンク

### ✍️ レビュー・期待度メモの投稿

映画の鑑賞状況に応じて、2 種類の投稿を使い分けられます。

**🎬 観た！（感想）**

- 鑑賞後の感想を投稿
- スライダー UI で評価点を設定
- 観た後の気分に合わせた感情タグを選択

**💗 観たい！（期待）**

- 鑑賞前の期待や気持ちを記録
- 期待している感情をタグで表現

### ⭐ 評価機能

映画に対する評価を 1.0 ～ 10.0 の数値で設定できます。

### 💗 いいね機能

ほかのユーザーのレビューに対して、いいねを付けられます。自分の投稿にはいいねできない設計です。

### 💬 コメント機能

レビューにコメントを投稿し、ほかのユーザーと感想を共有できます。

コメント欄には開閉 UI を採用し、自分のコメントは編集・削除できます。

### 🔖 ウォッチリスト（みたい！）

気になった映画をリストに保存し、必要に応じて解除して管理できます。

### 🔔 通知機能

いいねやコメントなどに関する通知を確認できます。

### 📌 マイページ・コミュニティ

- **コミュニティ：** ユーザーの投稿をタイムライン形式で表示します。データベースに作品情報が保存されていない場合に、TMDB API から作品タイトルなどを補完して表示する処理を実装しています。
- **マイページ：** 自分の投稿や活動履歴を確認し、映画の感想や期待を振り返ることができます。

## 3. 感情タグについて

MovieMood では、映画のジャンルだけでは表現しきれない感情に着目し、4 種類の感情タグを採用しています。

| 感情タグ      | 表現したい気持ち                         |
| :------------ | :--------------------------------------- |
| **#号泣**     | 涙が出るほど感動したい・感動した         |
| **#スカッと** | 爽快感を味わいたい・味わえた             |
| **#ハラハラ** | 緊張感やスリルを楽しみたい・楽しめた     |
| **#キュン**   | ときめきや恋愛感情を味わいたい・味わえた |

鑑賞前の投稿では「#号泣しそう」「#スカッとしそう」「#ハラハラしそう」「#キュンとしそう」のように、期待している気持ちを表現します。

### 感情タグを採用した理由

#### 1. 直感的に選びやすい

専門的なジャンル名ではなく、日常的に使う言葉を採用することで、自分の気分に合ったタグを選びやすくしています。

#### 2. 映画を選ぶきっかけになる

「今日は泣ける映画が観たい」「スカッとしたい」など、その日の気分をもとに映画を探すきっかけになります。

#### 3. 鑑賞前と鑑賞後の気持ちを表現できる

観る前の期待と、実際に観た後の感情をそれぞれ記録することで、映画鑑賞の体験をより豊かに残せるようにしています。

## 4. 使用技術

| 分類                 | 技術                            |
| :------------------- | :------------------------------ |
| **バックエンド**     | PHP 8.x                         |
| **フレームワーク**   | Laravel                         |

- **Laravel：** ルーティング、コントローラー、データベース操作など、Web アプリケーションの基本的な構成を実装するために使用しています。

- **Tailwind CSS：** ヘッダーや各画面のレイアウト、色、余白などを調整し、統一感のある UI を実装しています。
- **Alpine.js / Vanilla JavaScript：** アコーディオンの開閉や検索候補の表示など、画面のインタラクティブな動作に使用しています。
- **TMDB API：** 映画のポスターや作品情報、作品タイトルなどの取得に使用しています。
- **OpenWeatherMap API：** 天気情報の取得と、空模様に合わせた映画提案に使用しています。
- **Docker：** 開発環境を構築し、アプリケーションを実行するために使用しています。

## 6. 環境構築・起動方法

### 必要な環境

- PHP 8.x
- Composer
- Node.js / npm
- Docker
- Git

### 1. リポジトリを取得

ターミナルで以下のコマンドを実行します。

```bash
git clone https://github.com/ivyc259001abe/MovieMood.git
cd MovieMood
```

### 2. PHP の依存パッケージをインストール

```bash
composer install
```

### 3. 環境設定ファイルを作成

```bash
cp .env.example .env
php artisan key:generate
```

### 4. データベースを設定・マイグレーションを実行

`.env` のデータベース接続情報を設定後、以下を実行します。

```bash
php artisan migrate
```

### 5. フロントエンドの依存パッケージをインストール

```bash
npm install
```

### 6. Docker を起動

プロジェクト直下のターミナルで実行します。

**通常起動**

```bash
docker compose up -d
```

**イメージを再ビルドして起動する場合**

初回起動時や Docker の設定を変更した場合など、イメージの再ビルドが必要なときに実行します。

```bash
docker compose up -d --build
```

**コンテナの起動状態を確認**

```bash
docker compose ps
```

### 7. フロントエンドの開発サーバーを起動

必要な場合は、別のターミナルで実行します。

```bash
npm run dev
```

Docker を使用せず Laravel の開発サーバーを利用する場合は、環境に応じて以下を実行します。

```bash
php artisan serve
```

> **注意：** 起動方法やアクセス先 URL は、プロジェクト内の Docker 設定およびポート設定に合わせてください。データベースの起動やマイグレーションが必要な場合も、実際の構成に従って実行してください。

## 7. 環境変数の設定

映画情報や天気情報を取得するために、必要な API キーを `.env` に設定します。

以下は設定例です。実際に使用する環境変数名は、プロジェクト内の `config/services.php`、コントローラー、API 呼び出し処理などの記述に合わせてください。

```dotenv
TMDB_API_KEY=取得したTMDBのAPIキー
OPENWEATHER_API_KEY=取得したOpenWeatherMapのAPIキー
```

### 注意事項

- `.env` には API キーなどの機密情報を保存します。
- `.env` を GitHub に公開しないでください。`.gitignore` に含まれていることを確認してください。
- `.env.example` には実際の API キーではなく、設定項目の例を記載してください。
- API キーをソースコードに直接記述しないようにしてください。
